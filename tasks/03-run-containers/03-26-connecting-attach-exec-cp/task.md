# Task 03-26: Connecting to Running Containers: podman attach, podman exec -it, and podman cp

## Scenario
Understand the critical difference between **`podman attach`** (attaches to PID 1's stdin/stdout — pressing `Ctrl-C` or `exit` terminates the container unless you detach via `Ctrl-P, Ctrl-Q` or custom `--detach-keys`!) and **`podman exec -it`** (spawns a separate interactive child process whose exit leaves PID 1 untouched).

Setup started interactive console daemon `console-repl` (`-d -i -t`), which listens on PID 1 stdin for commands (`UNLOCK <passcode>`) and writes `/var/run/repl-unlocked.token` when unlocked!

## Requirements
1. Inspect `/etc/repl-passcode` inside `console-repl` using an interactive/shell session (`podman exec -it console-repl /bin/sh` or `podman exec`) to read the required passcode.
2. Connect to `console-repl`'s PID 1 stdin using `podman attach` (detaching safely with `Ctrl-P, Ctrl-Q` — or piping `"UNLOCK <passcode>"` via `podman attach --sig-proxy=false` / interactive attach) to send `UNLOCK <passcode>`, **keeping `console-repl` running**!
3. Once `/tmp/repl-unlocked.token` is generated by PID 1 inside `console-repl`, copy it out to `/home/student/workspace/03-26/unlocked.token` using `podman cp`, and copy `/home/student/workspace/03-26/operator-ack.txt` (containing `ACK_BY_STUDENT`) into `console-repl:/tmp/operator-ack.txt`.
